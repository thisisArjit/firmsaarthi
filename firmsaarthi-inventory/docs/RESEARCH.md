## Six-hour follow-up — 28 October 2026

Engineering evidence: [Cloudflare D1 batch/session contract](https://developers.cloudflare.com/d1/worker-api/d1-database/) documents transactional batch rollback and primary-first sequentially consistent sessions; [supported SQL](https://developers.cloudflare.com/d1/sql-api/sql-statements/) documents SQLite compatibility. Decision: never spread BEGIN/COMMIT over remote calls. Insert movement and return its scoped replay inside one batch; triggers validate live membership, quantities and count version at insertion. This closes an adjustment race in the earlier synchronous reference design when ported to remote D1. Local contract tests do not establish hosted support/performance.

Adjacent sales review: [ERPNext stock reservation](https://docs.frappe.io/erpnext/stock-reservation) documents warehouse/quantity reservations against sales orders or pick lists and explicit unreservation. I3 gap remains on-hand versus reserved versus available stock, fulfilment and release/expiry. Decision: do not model an order or reservation as an actual stock issue; finish I1 before adding these workflows. No reservation capability was implemented or advertised. The attempted Zoho sales-order workflow URL was unavailable, so no new Zoho claim is based on it.
