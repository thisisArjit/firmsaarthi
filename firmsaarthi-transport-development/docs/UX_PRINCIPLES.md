# Logistrace simplicity rules

Use the shared SortableTable for tabular registers: sortable headings, bounded two-axis scrolling, sticky headings and stable editable rows. Prefer Manually entered for payment-origin presentation; preserve unavailable dates and actual stored provenance.

User instruction, 25 October 2026: “Focus on user simplicity as well. Keep it very sober and easy to use.” Apply this to every future milestone, including trip execution and staff automation.

## Everyday use

- Organize by the user's tasks: Consignments, Billing, Suppliers, Accounts, Staff, Tracking and Settings. Put related pages within these sections. Respect existing owner/member access.
- Give each page a clear title and one obvious next action. Start on the consignment list. Do not add a decorative dashboard or duplicate navigation for the same task.
- Show essential fields first. Keep optional rate, weight, advances and invoice references in clearly named expandable sections. Existing nondefault values should be discoverable when editing. A booking currently needs seven fields.
- Use plain labels: Create invoice, Review invoice, Save invoice, Record payment. Distinguish a payment record from sending funds. Keep unknown, imported and unconfigured states honest.
- Start list filters with customer and record number. Show an active count for additional filters and provide a visible way to clear them. Summary totals must follow the current filtered records.
- Combine related details in readable table cells. Keep exports and uncommon actions accessible without surrounding every record with buttons. Keep critical payment states, missing costs and excess payments visible.
- On phones, provide a labelled Menu control, close it after navigation, retain sign-out access and prevent page overflow. Wider financial tables may scroll within their own container. Use comfortable touch targets and keyboard focus indicators.

## Visual style

White surfaces, light gray background, restrained blue-gray primary action, modest borders and minimal shadow. Use color to explain status. Avoid gradients, decorative metrics, promotional copy, busy cards and unnecessary animation. Keep text readable; don't achieve density by shrinking essential text.

## Financial integrity

Simplicity must preserve required review, amounts, dates, tax treatment, roles, stale-edit checks and audit history. Expand details progressively; do not hide material consequences or silently change accounting semantics. Keep short warnings beside the action they explain. Company P&L remains provisional and provider integrations remain unconfigured until the relevant evidence and access exist.

## Release checks

Exercise a complete booking-to-invoice journey, supplier cost/payment entry and relevant owner/member access. Check desktop and a 390 px phone viewport. Verify critical status labels, optional-section behavior, filtering, table scrolling and browser errors. Use synthetic local records; remove them before packaging. Future pilot interviews should measure task completion and error recovery with transport operators rather than asking only whether a screen looks attractive.
